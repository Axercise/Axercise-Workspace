# Axercise Workspace — บันทึกการออกแบบ

อัปเดต: 16 พฤศจิกายน 2026

สถานะ: ทำแอป Next.js และระบบเชื่อมต่อแล้ว สร้างพื้นที่ข้อมูล Hermes ชุดใหม่ในโปรเจกต์ ต้องตั้งค่าบัญชีและทดสอบบริการจริงต่อ ดูรายละเอียดใน `VERIFICATION.md`

## 1. สิ่งที่ผู้ใช้ยืนยันแล้ว

- Axercise Workspace เป็นชื่อพื้นที่หรือโหมดทำงานส่วนตัวของผู้ใช้
- ใช้งานบนเครื่อง Windows ของผู้ใช้ผ่าน localhost และต้องเปิดได้ด้วยคำสั่ง `axercise`
- ใช้ Next.js เป็นหน้า Workspace และเชื่อมกับ Hermes AI Agent ที่ติดตั้งอยู่แล้ว
- ต้องการใช้บัญชี GPT ที่ใช้อยู่ และ OpenRouter ซึ่งมีโมเดลฟรีให้เลือก
- UI อ้างอิงภาพ `C:\Users\dadby\Desktop\Axercise Workspace UI.png`: พื้นหลังดำ แถบซ้ายสีเทา แชทตรงกลาง ปฏิทินขวาบน และ To-do ขวาล่าง
- Brain Dump เปิด–ปิดได้ใน popup กลางจอหรือแผงสไลด์ ผู้ใช้มอบหมายให้เลือกและออกแบบรายละเอียด UI ได้
- ให้คิดแผนก่อนลงมือ และถามผู้ใช้เรื่องการตัดสินใจด้านระบบที่ยังไม่ชัดเจน ตามข้อกำหนดท้าย `Project_Plan.md`
- การเชื่อมต่อเดิมยังไม่สมบูรณ์: Notion ใช้ได้บางส่วน, Google Calendar ยังเชื่อมไม่สำเร็จ, Discord เคยตั้ง gateway และแยกบอทไว้หลายตัวเพื่อแยกความจำ
- แชทใน Discord และ Workspace เริ่มต้นแยก Session แต่ต้องเลือกใช้ Session เดียวกันได้
- ผู้ใช้ต้องการให้ Hermes ทำงานได้เต็มที่ภายใต้สิทธิ์บัญชี Windows ของผู้ใช้
- ผู้ใช้เลือกเริ่มบอท/Profile ใหม่ทั้งหมดและเริ่มความจำใหม่ แทนการนำ Profile เดิมมาใช้ต่อ
- ผู้ใช้เลือกเก็บข้อมูล Notion ชุดใหม่สำหรับ Axercise
- การเริ่มใหม่จะใช้พื้นที่ข้อมูลใหม่และเก็บของเดิมแยกไว้ก่อน ยังไม่มีคำสั่งให้ลบข้อมูลหรือถอนการติดตั้งเดิม
- ผู้ใช้ยืนยันชื่อบทบาทเริ่มต้น: Hermes หลัก, เลขาส่วนตัว และ Developer
- ผู้ใช้ยืนยันให้ระบบทำงานเบื้องหลังต่อจนสั่ง `axercise stop`
- ผู้ใช้ยืนยันให้เก็บฉบับร่างงานและ Brain Dump ในเครื่อง แล้วกดส่งเข้า Notion เมื่อกลับมาออนไลน์
- ผู้ใช้ยืนยันฐานข้อมูล Notion ใหม่สองชุด: Tasks และ Brain Dump ตามโครงสร้างที่เสนอ

## 3. แนวทาง UI ที่เลือก

### โครงหน้าหลัก

- คงเลย์เอาต์สามคอลัมน์ตามรูป พื้นที่แชทเป็นพื้นที่หลักและขยายตามความกว้างหน้าจอ
- Container ใช้เต็มความกว้าง viewport และเว้นขอบขวา desktop 12px เพื่อให้แผง widget อยู่ใกล้ขอบหน้าจอ รวมถึงจอที่กว้างเกิน 2200px
- บนจอ desktop: แถบซ้ายประมาณ 248px และ widget ด้านขวาประมาณ 356px โดยปรับตามขนาดจอ
- อัปเดตตามคำขอวันที่ 17 พฤศจิกายน 2026: ใช้สีตามสัดส่วนเชิงภาพ 60/30/10 — canvas ดำ `#151515`, พื้นผิวเทา `#202020`–`#2d2d2d`, accent ขาว `#e5e5e5` สำหรับการเลือกและปุ่มสำคัญ ผู้ใช้เลือกโทนเทา–ดำ–ขาวและแสงขาวทั้งระบบ
- การ์ดมุมโค้ง 14–20px ระยะห่าง 16–24px แยกชั้นด้วยเส้นขอบและเงาอ่อน พร้อม glow สีขาวนุ่มเฉพาะจุดสำคัญ
- ใช้ Noto Sans Thai variable แบบ self-hosted พร้อม OFL ใน `src/app/fonts/`; ข้อความแชทและช่องกรอก 16px, ข้อความใช้งาน 14–16px, ข้อความรอง 12–14px และป้ายตกแต่ง 10–11px
- hover/focus เปลี่ยนสีและเงาใน 180–240ms; popup/drawer เปิด–ปิดใน 180–320ms และเคารพ `prefers-reduced-motion`
- หน้าจอเล็กยุบ sidebar เป็น drawer และเปิด Calendar/To-do ผ่านปุ่ม โดยคงพื้นที่แชทให้อ่านได้
- แสดงสถานะกำลังโหลด ว่าง เชื่อมต่อไม่ได้ และข้อมูลที่บันทึกไม่สำเร็จให้ชัดเจน

### แถบซ้าย

- ชื่อ Axercise ด้านบน ปุ่มเริ่มแชท และกลุ่ม Agent กับ Session ที่มองแยกกันได้
- Session ต้องอ้างอิงตัวตนของบทสนทนาใน Hermes จริงเมื่อเชื่อมระบบแล้ว
- ด้านล่างมีปุ่ม Brain Dump, การตั้งค่า และสถานะการเชื่อมต่อ
- ให้กลุ่ม Agent อ้างอิงพื้นที่ข้อมูลใหม่ของ Hermes, Secretary และ Developer ที่แยกความจำ แล้วแสดง Session ภายใน Agent ที่เลือก

### แชทตรงกลาง

- ส่วนหัวแสดง Agent/Session และตัวเลือก Provider/Model ที่ใช้งานได้จริง
- แสดงข้อความแบบ streaming และสถานะเครื่องมือที่ Hermes กำลังใช้
- ช่องพิมพ์อยู่ด้านล่าง รองรับแนบรูป วาง screenshot ตัวอย่างรูปก่อนส่ง และปุ่มหยุดการตอบ
- ระบุเมื่อโมเดลไม่รองรับภาพหรือการเรียกใช้เครื่องมือ และให้เลือกโมเดลที่รองรับ
- ประวัติและการเปลี่ยน Agent ต้องมีขอบเขต Session ที่แน่นอนตามแบบระบบที่จะตกลง

### ปฏิทินขวาบน

- แสดงวันที่และรายการนัดของวันที่เลือก พร้อมเลื่อนวันและปุ่มเพิ่มนัด
- คลิกนัดเพื่อเปิดรายละเอียดและแบบฟอร์มแก้ไข
- แสดงเวลาอิง Asia/Bangkok โดยตรวจ timezone ของกิจกรรมจาก Google Calendar ด้วย
- เมื่อมีการแก้ข้อมูลผ่านหน้าเว็บหรือ AI ให้ widget ดึงข้อมูลที่ยืนยันแล้วกลับมาแสดง

### To-do ขวาล่าง

- แสดงสี่หมวด Eisenhower: ทำทันที, วางแผน, มอบหมาย และตัดออก
- Widget ใช้รายการแบบกะทัดรัดพร้อมหมวดและ Deadline; หน้าดูทั้งหมดมีพื้นที่จัดการครบทั้งสี่หมวด
- คลิกงานเพื่อเปิด modal รายละเอียด แก้ไข ทำเสร็จ หรือลบ
- ออกแบบให้แสดงงานเลยกำหนดและงานไม่มี Deadline ได้

### Brain Dump

เลือกใช้ **แผงสไลด์จากขวา** เป็นรูปแบบหลัก เพื่อจดไอเดียได้โดยไม่เปลี่ยนหน้าแชท

- ปุ่มเปิดอยู่ใน sidebar และแสดงชื่อกำกับชัดเจน
- เปิดพร้อมฉากหลังมืดบาง ๆ ความกว้างประมาณ 440–480px และเต็มความกว้างบนมือถือ
- ส่วนบนเป็นช่องจดด่วนและปุ่มบันทึก ใช้ `Ctrl+Enter` เพื่อส่งบันทึกได้
- ส่วนล่างแสดงรายการไอเดียล่าสุดและเปิดอ่านรายละเอียดได้
- กดปุ่มปิดหรือ `Esc` เพื่อปิด; จัด focus ให้อยู่ในแผงขณะเปิดและคืนไปยังปุ่มเดิมเมื่อปิด
- Animation ประมาณ 200ms และเคารพการตั้งค่า reduced motion
- เมื่อส่งบันทึก ให้แสดงว่ากำลังบันทึกจนได้รับผลจาก Notion; ถ้าล้มเหลวให้เก็บข้อความในแบบฟอร์มไว้เพื่อส่งใหม่
- เก็บฉบับร่างใน localStorage ของ browser นี้ และส่งเข้า Notion เมื่อผู้ใช้กดส่ง ไม่ส่งฉบับร่างอัตโนมัติ

## 4. แนวทางเชื่อมระบบที่นำมาใช้

ลำดับการทำงานที่เสนอ:

`Browser → Next.js ฝั่ง server → Hermes API บนเครื่อง → Provider/เครื่องมือ/บริการที่เชื่อม`

- ให้ Next.js เป็นหน้าจอและชั้นเชื่อมต่อกับโปรแกรม Hermes ที่ติดตั้งอยู่ โดยสร้างชุด Profile/Memory/Session ใหม่สำหรับ Axercise
- เอกสารใน Hermes ที่ติดตั้งมี API Server แบบ OpenAI-compatible พร้อม streaming, ข้อมูลโมเดล และ conversation continuity จึงควรตรวจ endpoint เหล่านี้ก่อนเขียน gateway เพิ่ม
- ใช้ Discord gateway ของ Hermes หากรองรับงานที่ต้องการ แทนการเริ่มบอทอีกตัวทันทีตามแผนฉบับแรก
- Credential และ token อยู่ฝั่ง server; browser รับเฉพาะข้อมูลและสถานะที่จำเป็น
- Notion เป็นแหล่งข้อมูลหลักของ To-do และ Brain Dump ส่วน Google Calendar เป็นแหล่งข้อมูลของนัดหมาย ตาม Requirement เดิม
- สร้างฐานข้อมูล Notion ชุดใหม่ โดยเสนอแยก Tasks และ Brain Dump; รายละเอียด property และหน้าที่ใช้วางฐานข้อมูลยังต้องสรุปก่อนสร้างจริง
- การแก้ไขผ่านเว็บและ AI ควรผ่านกติกาข้อมูลและ connector ชุดเดียวกัน เพื่อให้ widget แสดงผลตรงกัน
- ต้องกำหนดเจ้าของงานแจ้งเตือนให้ชัดเจน เพื่อลดการแจ้งเตือนซ้ำระหว่าง Hermes cron กับส่วน Workspace
- หน้าแชทส่ง provider/model ให้ Hermes เป็นรายคำขอ ส่วนค่าตั้งต้นอยู่ในหน้าตั้งค่า โดยใช้การจัดการสถานะ Session ของ Hermes
- Agent/Persona, Session และ Subagent ที่ถูกมอบหมายงานชั่วคราวเป็นคนละแนวคิด ต้องกำหนดความสัมพันธ์ก่อนทำ sidebar และ router
- คงการแยกความจำระหว่าง Profile แม้เปิดให้เลือก Session ร่วมกันระหว่าง Discord กับ Workspace ภายใน Profile เดียวกัน
- ตรวจ process และ gateway เดิมก่อนเริ่มระบบใดเพิ่ม รวมถึงตรวจข้อจำกัด concurrency ของ Hermes; เอกสาร Profile ของรุ่นที่ติดตั้งระบุว่าไม่ควรให้หลาย agent process เขียน Hermes home เดียวกันพร้อมกัน
- นโยบายเครื่องมือที่ต้องรองรับคือทำงานได้เต็มที่ตามสิทธิ์ Windows ที่ผู้ใช้เลือก โดยยังต้องตรวจว่าเส้นทาง API ของ Hermes รองรับนโยบายนี้อย่างไร

แนวทางนี้เป็นข้อเสนอจากความสามารถที่พบ ยังไม่ได้ทดสอบการเชื่อมกับ Hermes instance ที่กำลังทำงาน

## 5. GPT และ OpenRouter

### GPT ผ่านบัญชี ChatGPT/Codex

Hermes มีตัวเลือก `ChatGPT or Codex Subscription` ผ่าน `hermes model` และเก็บการยืนยันตัวตนในระบบของ Hermes ตาม [เอกสารผู้ให้บริการของ Hermes](https://hermes-agent.nousresearch.com/docs/integrations/providers)

ต้องตรวจการล็อกอิน สิทธิ์ของบัญชี และรายการโมเดลที่ระบบคืนมาจริงก่อนยืนยันว่าเลือกโมเดลเดียวกับบทสนทนานี้ได้ การใช้บัญชีเดิมไม่ได้หมายความว่าจะนำประวัติหรือความจำจากแชทนี้ไปใช้ได้อัตโนมัติ ดู [เอกสาร OpenAI เรื่องการใช้แผนในแอปอื่น](https://help.openai.com/en/articles/20001542-using-your-chatgpt-plan-in-other-apps-and-sites)

แยกสถานะการเชื่อมด้วยบัญชีออกจากการใช้ API key ซึ่งมีรูปแบบการคิดค่าบริการของ API ตาม [เอกสารการยืนยันตัวตนของ OpenAI](https://learn.chatgpt.com/docs/auth)

### OpenRouter

มี config ชี้ OpenRouter อยู่แล้ว แต่ยังไม่ได้เรียกทดสอบบัญชีหรือโมเดล

โมเดลฟรีมีข้อจำกัดการใช้งานและความสามารถแตกต่างกัน จำนวน token ที่โมเดลรองรับต่อบริบทไม่ได้แปลว่าเป็นโควตาใช้งานฟรีไม่จำกัด ดู [ข้อจำกัดการใช้งาน OpenRouter](https://openrouter.ai/docs/api_reference/limits)

UI ควรใช้รายการโมเดลและความสามารถจากระบบจริง แสดงกรณีโมเดลไม่พร้อมหรือหมดโควตา และให้ผู้ใช้เลือกวิธี fallback ก่อนนำไปทำงานอัตโนมัติ

## 7. เรื่องที่ต้องตกลงต่อก่อนทำส่วนที่เกี่ยวข้อง

- ผู้ใช้เลือกหน้า Notion และกรอกข้อมูล Integration ผ่านหน้าตั้งค่า ก่อนสร้างฐานข้อมูลจริง
- ผู้ใช้เลือกบัญชี/ปฏิทิน Google และเวลาแจ้งเตือนในหน้าตั้งค่า ค่าเริ่มต้นปฏิทินคือ primary และเวลาเตือน 15 นาที
- ผู้ใช้สร้างบอท Discord ใหม่และใส่ Token/User ID/Channel ID ให้บทบาทที่ต้องการเชื่อม
- เมื่อโมเดลล้มเหลว ระบบแสดงข้อผิดพลาดและให้เลือกโมเดลใหม่ ไม่เปลี่ยนไปใช้โมเดลเสียค่าใช้จ่ายเอง

ไม่จำเป็นต้องถามทุกเรื่องพร้อมกัน ให้ตกลงเป็นส่วนตามลำดับงาน

## 8. ลำดับงานที่ดำเนินการ

1. สรุปคำตอบด้านระบบและตรวจความสามารถของ Hermes ที่จะใช้จริง
2. ทำ UI ใน Next.js ตามภาพและแนวทางในเอกสารนี้ พร้อม Brain Dump drawer
3. เชื่อมแชท, Session, model picker และภาพแนบกับ Hermes พร้อมตรวจ error และ cancellation
4. เชื่อม Notion/Calendar โดยใช้ connector และ schema ที่ตกลงแล้ว ทดสอบทั้งการแก้ด้วยมือและ AI
5. เชื่อม Discord และงานแจ้งเตือนตามนโยบาย Session และสิทธิ์ที่เลือก
6. ทำคำสั่ง `axercise` สำหรับเปิด localhost จัดการ process และทดสอบการเริ่ม–หยุดบนเครื่อง Windows จริง

แต่ละส่วนต้องทดสอบพฤติกรรมที่ใช้งานจริง ไม่ถือว่า UI ตัวอย่างหรือการมีไฟล์ config เป็นหลักฐานว่า integration เสร็จแล้ว

โค้ดของส่วนเหล่านี้ทำแล้วและผ่าน build/contract tests การเชื่อมกับบัญชีจริงยังรอการตั้งค่าโดยผู้ใช้ ตามรายละเอียดใน `VERIFICATION.md`
